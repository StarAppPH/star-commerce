# Pub/Sub map

> Generated by server/pubSubMap.py from pubsub_map.json. Do not edit. Regenerate: `cd server && python pubSubMap.py --write` (AppCreator also runs it). `python pubSubMap.py --explain <topic>` prints live file:line.

**Legend.** A flow is one publisher -> consumer edge. *Payload* is how the publisher's return value was typed: `modelDump`, `dictLiteral`, `persistedDump` (a db.create/update of a model dump), `responseModel` (the route_config model), `declared` (PUBSUB_PAYLOAD_MODELS) or `unknown`; a typed return takes the unknown types of its values from the responseModel, else the PUBSUB_PAYLOAD_MODELS model. *Compat*: `ok`, `issues` (each fails the tests of both repos of the flow; nothing suppresses one) or `unverified` (payload unknown, or a side read from the snapshot could not be re-checked). Issues: `undeclared` (a required key the publisher never sends), `nullable` (the publisher may send null where the consumer needs a value), `literal`, `numericNarrowing` (float into int), `forbiddenExtra`. Info: `deadBranch`, `deadRead`, `maybe` (the publisher may omit a key the consumer needs), `unverified`, `dynamicKey` (the handler reads a key of this path that the map cannot resolve statically; not checked). *Reads* flags include `lenient` (read inside a `try/except Exception` that does not raise again; its issues still fail, as the handler would drop the message silently) and `noneToValue` (every before validator of the field provably turns None into a value, so null is accepted). A row that is not `ok` shows the publisher field, type and presence. Paths: `a.b` is a key, `a[]` a list element. Static, type-level only: value-dependent logic (e.g. mapping type=='services' to None, then dereferencing it) is not modelled; ok means the declared types line up at every path read. test_pubSubContracts replay is the ground truth.
